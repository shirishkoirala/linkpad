# Protocol v1

TLS 1.3 WebSocket, explicit `wss://HOST:4747/ws`. Native clients only; HTTP Origin headers are denied. Both peers present persistent self-signed identity certificates. Device ID is lowercase SHA-256 of the DER certificate, not a claimed JSON name. The client pins the server certificate obtained through a trusted channel; TLS CertificateVerify proves possession of both private keys. Server accepts an unknown certificate at TLS level **only** to permit pairing; application access is denied until authenticated pairing completes.

UTF-8 JSON text frames, maximum 4096 bytes on the Go receiver. Each message has `version: 1` and `type`. Unknown fields are reserved for future extensions. No compression, screen streaming, arbitrary commands or code loading.

1. Desktop operator starts with `-pair` and gives the controller the displayed fingerprint and 256-bit random secret through a trusted channel. Window lasts two minutes, for one device.
2. Controller sends `{"version":1,"type":"pair","token":"<secret>","capabilities":["pointer.v1"]}`. The server atomically persists that TLS client certificate fingerprint before consuming the secret. Failure does not grant trust. An already trusted controller instead sends `hello` with requested capabilities and no secret.
3. Server responds `{"version":1,"type":"ready","capabilities":["pointer.v1"]}`. List is the intersection of requested and locally enabled, available plugins. An empty list is a successful connection with no pointer permission.
4. `{"version":1,"type":"pointer","dx":10,"dy":-3}` moves relative to the current global cursor position in desktop coordinates. Omitted dx/dy default to 0. Optional `button` is `left` or `right`, producing a complete press/release at the resulting location. There is no held-button/drag support. Integers are bounded to [-500,500]. Backend success returns `ack`; denied/failed actions return `error` and close the session. Pointer packets before negotiation never reach a plugin.
5. `{"version":1,"type":"key","key":"up"}` presses and releases one arrow key (`up`, `down`, `left` or `right`); it carries no movement or button. Negotiated as `key.v1`, itself gated by the same pointer permission as the cursor.
6. A subsequent `hello` is a keepalive, returning `ack`. Go allows 90 seconds between application messages. Android sends a heartbeat every 30 seconds while foregrounded. Handshake deadline 10 seconds, writes 5 seconds. Go sleeps 10 ms after a pointer acknowledgement per connection; this is basic pacing, not a global abuse quota. Android allows one pointer packet awaiting acknowledgement and throttles motion to 25 Hz, dropping intermediate movement; click while pending is also dropped.

One request/ack flow at a time is recommended. No request IDs, retries or exactly-once delivery guarantees yet. WebSocket preserves frame order within each session. Reconnect uses the same private identity and verifies the same pin; all connections renegotiate capabilities. Pairing grants the peer all locally enabled capabilities for this slice; there are no per-device permission prompts yet. Both Go peers can listen or initiate a connection, although the controller-to-receiver pointer session is directional.

`v1/message.schema.json` documents the wire shape. Runtime tests exercise both parsing and real TLS/WebSocket sessions; JSON Schema itself is not loaded at runtime. Future plugin families require a new dispatcher and schema extension.
